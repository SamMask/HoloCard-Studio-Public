# HoloCard-Studio 規格 v0.1（立體卡牌工坊）

> 2026-10-12 主對話（Claude）依使用者需求整理；四項取捨由使用者決定（見 §9）。本檔是產品與技術的權威規格；結構細節在 `ARCHITECTURE.md`、資料格式在 `SCHEMA.md`、畫面在 `DESIGN.md`。

## 1. 一句話與目標

打開網頁，上傳幾張圖，疊成一張**可以拖著轉、有立體深度、會隨角度反光（鐳射）**的卡片；自動保存，也能匯出成卡片檔、圖片或轉動影片分享。

- **成功的樣子**：沒有教學也能在 3 分鐘內做出第一張會轉的立體卡；轉起來的立體感與反光接近使用者給的參考（Threads 立體鐳射卡、寶可夢卡牌 Pocket 可轉的 3D 卡）。
- **由來**：OK_Games 的 BACKLOG（2026-10-09）「立體卡牌 DIY 工坊」等級 1；2026-10-12 使用者決定獨立成專案。之後 OK_Games 的抽卡教學遊戲會讀同一種卡片檔（§5.4）。
- **產品原則**：使用者體驗第一、美觀第二。程式能自動處理的就自動（自動排深度、自動存檔、自動縮圖），不要讓使用者面對技術設定。

## 2. 使用者與情境

- **主要使用者**：使用者本人（會用生圖做透明角色圖）。會拖圖、會調滑桿，不會寫程式、不懂 3D 名詞。第一版朋友不直接用工坊，只看匯出的 PNG／影片（使用者 2026-10-13）。
- **典型情境**
  1. 有一張去背角色 PNG 和一張背景圖 → 拖進來 → 角色自動浮在背景前面 → 拖著轉看立體感 → 調鐳射強度 → 存成 PNG 貼社群。
  2. 做一張正反兩面的塔羅牌：正面三層（背景、角色、前景花瓣）、背面一張卡背圖、開卡框 → 匯出卡片檔備份，之後匯入可以再改。
  3. 想把成品給不會用工具的人看 → 錄一段自動轉一圈的影片／GIF。

## 3. 名詞（統一語彙）

| 名詞 | 意思 | 程式名稱 |
|---|---|---|
| 卡片 | 一個作品：比例、正面、背面、卡框、鐳射設定 | `Card` |
| 面 | 卡片的正面或背面，各有自己的圖層 | `face: 'front' \| 'back'` |
| 圖層 | 一張圖，有深度、位置、大小、是否顯示 | `Layer` |
| 底圖 | 每一面最後方那層，可以是不透明圖（背景） | `Layer.role = 'base'` |
| 立體層 | 帶透明的圖，浮在底圖前面，深度不同 | `Layer.role = 'depth'` |
| 深度 | 圖層「浮起來」多少；轉動時深度越大的層位移越多（視差），前後順序也由它決定 | `Layer.depth`（底圖 0、立體層 1～100） |
| 卡身 | 卡片本體：顏色、圓角、固定的薄厚度 | `Card.bodyColor`、`Card.cornerRadius` |
| 卡框 | 卡面邊緣的框，可開關、可調寬度與顏色 | `Card.frame` |
| 鐳射 | 隨角度流動的彩虹反光 | `Card.holo` |
| 閃星 | 鐳射裡隨角度一閃一閃的小亮點（不是粒子特效） | `Card.holo.sparkle` |
| 卡片檔 | 一個檔案包含一張卡的所有圖與設定（副檔名 `.holocard`） | §5.4、`SCHEMA.md` |
| 我的卡片 | 存在瀏覽器裡的卡片清單 | `Library` |

## 4. 範圍

### 4.1 第一版要做（等級 1，使用者 2026-10-12 選）

1. **新卡片**：選比例（標準卡 63×88、塔羅 70×120），空白卡上就能先轉動預覽。
2. **上傳圖片**：拖曳或按鈕上傳 PNG／WebP／JPG；每面最多 8 層。
   - 有透明 → 當立體層，**自動排深度**（後上傳的在前面），之後可調。
   - 沒透明 → 只能當底圖（背景）；如果已經有底圖就問要不要取代；提示「要立體效果，請用去背過的 PNG」。
   - 太大的圖自動縮到最長邊 2048 px；存成 WebP（保留透明）。
3. **圖層編輯**：圖層清單（縮圖、名稱、顯示開關、刪除、拖拉排序＝交換深度）；選中的圖層可調深度、位置、大小（直接在卡上拖曳／縮放把手，或滑桿）；圖層對齊（置中、填滿卡面；立體層「填滿」時程式自動多放大一點，轉動時不露出圖的邊）。前後順序只看深度。
4. **正面／背面**：切換編輯（編輯背面時卡片自動轉到背面）；背面沒有圖層時，程式畫素色卡背（卡身色＋淡淡的對稱花紋），上傳圖片就取代；沒有底圖的面顯示卡身顏色。
5. **卡身與卡框**：卡身顏色、圓角（和卡框開關無關）、固定的薄厚度（側面看得到邊）；卡框可開關、調寬度與顏色（幾個預設＋自選）。
6. **立體預覽**：
   - 滑鼠拖曳轉動（可以翻到背面），放開後慢慢回正到最近的一面（正面或背面；可關）；滾輪縮放。
   - 「展示」模式：自動緩慢擺動。
   - 景深：各層依深度做視差位移、前層對後層有淡淡陰影（§5.2）。
7. **鐳射**：強度、彩虹色帶寬度、閃星多寡（0＝沒有閃星）、作用範圍（全卡／指定圖層／只在卡框，閃星也照同一個範圍）；隨角度流動；強度 0＝關（閃星也一起關）；兩面套用同一組設定；選「只在卡框」但卡框關著＝沒有鐳射（介面提示）。（2026-10-15 註：鐳射範圍已改由每面一個「反光層」決定，可選整面、用圖層形狀或上傳黑白圖，見 T-417。）
8. **復原／重做**：Ctrl+Z／Ctrl+Shift+Z，畫面上也有按鈕；至少 50 步；一次拖曳（滑桿、移動、縮放）算一步。
9. **保存**：自動存到瀏覽器（動作完成就存、打字停 1 秒存、切走分頁或關閉前立刻存）；「我的卡片」清單（縮圖、改名、複製、刪除〔要確認〕）。
10. **匯出／匯入**：卡片檔 `.holocard`（可再編輯）；PNG 圖片（目前角度、畫布寬 1500 px，可選透明背景）；轉動影片 WebM 與 GIF（自動轉一圈，約 4 秒）。
11. **範例卡**：第一次開啟時有一張原創範例卡（3～4 層，Codex 生的原創角色），讓人先轉轉看、看懂分層。
12. **文字圖層**（使用者 2026-10-13 從第二版提前）：在卡上打字（卡名、說明、招式名之類）；可選字型（打包進專案的 2～3 套免費可商用中文字型，例如宋體、楷書或毛筆風；授權在施工時查清楚並記來源）、大小、顏色、位置、深度（和圖片圖層一樣會浮起來、有視差）；可選「印章」樣式（紅底方框白字）；鐳射「指定圖層」也能套到文字。字型不准執行時從網路抓（硬邊界 1）。

### 4.2 第一版不做（記在 BACKLOG）

- 粒子特效（火、電、水波、閃光；用某一層當特效來源）＝等級 2，第二版。
- 讓人寫程式或著色器（等級 3）：不做。
- 自動去背（AI 模型約 40～80 MB）：第二版再評估。
- 帳號、雲端、分享連結（要伺服器）：不做；分享靠匯出檔案。
- 開卡包演出：屬於 OK_Games 抽卡遊戲，不在工坊。（2026-10-15 註：工坊的新卡片面板已加入〔開一包〕，見 T-808。）
- 手機與窄畫面版（使用者 2026-10-13：娛樂用，只做桌機）。

## 5. 技術設計（SDD 摘要；細節見 ARCHITECTURE／SCHEMA）

### 5.1 形式與技術

- **純前端網頁程式**（使用者 2026-10-12 選）：`npm run dev` 後用瀏覽器開 `http://127.0.0.1:5190/`；所有圖片與資料都留在使用者電腦，不上傳任何地方。日後可 `npm run build` 成靜態網站放上使用者的網域，不用改寫。
- 技術棧：Node.js 22、TypeScript strict、Vite、three.js（與 OK_Games 同版 0.186.1；用新的 WebGPU 繪圖，見 §5.2）、Vitest。
- 只做桌機瀏覽器（Chrome／Edge 為主）；娛樂用，效能與相容性可以讓步給好看（使用者 2026-10-13）。
- 依賴清單（其他新增都要先問）：M1 裝 `three`、`@types/three`、`vite`、`typescript`、`vitest`、`@types/node`、`fflate`（卡片檔壓縮，約 8 KB）、`fake-indexeddb`（只用在測試）；M5 才裝 `gifenc`（GIF 編碼）。WebM 用瀏覽器內建 `MediaRecorder`，不另裝。實際安裝範圍以 `todo.md` 該任務寫的為準。
- 不用 React 等框架：介面元件不多，用原生 DOM＋小型自寫函式（照 OK_Games 做法）。

### 5.2 3D 做法

- **繪圖方式**（使用者 2026-10-13 選新的）：three.js 的 `WebGPURenderer`（`import from 'three/webgpu'`），著色程式用 TSL（`three/tsl`，three.js 的著色語言，同一份會轉成 WebGPU 與 WebGL2 用的程式），不寫 GLSL `ShaderMaterial`。瀏覽器不支援 WebGPU 時用 three.js 內建的自動退回 WebGL2，不另寫備案。
- 卡片＝three.js 場景裡的一組物件：薄的圓角卡身（`ExtrudeGeometry`，固定厚度，側面看得到邊）＋正反兩個卡面。
- **視差窗口做法**（2026-10-12 審查後定，避免圖層凸出卡外）：圖層**不離開卡面**。每一面只有一個圓角卡面網格，該面所有圖層在同一個 shader 裡由後往前合成（不靠 z 差排前後，斜看也不會閃爍；2026-10-13 T-103 實作後定），由 shader 把每層的取樣位置做位移，看起來像有深度的窗口；全部以卡片圓角輪廓遮罩，任何角度都不會凸出卡外。轉到超過 90° 看到的是背面。
- **位移公式只有一份**（2026-10-13）：每層的位移量由 `interact` 的純函式依「卡片角度 × 深度」算好（有測試），當 uniform（每影格傳給 shader 的數值）傳進去；shader 只負責套用，不自己再算一次。
- 景深陰影：在 shader 裡用前一層的 alpha 偏移取樣做淡淡陰影，不用 three.js 的 shadow map（透明 PNG 會投出整片矩形）。
- 鐳射：寫在各層材質的 shader 裡，用該層自己的 alpha 當遮罩（所以「指定圖層」做得到、彩虹貼著角色走），依視角與表面位置算彩虹色帶、加法混色；卡框另一個材質。
- 閃星（使用者 2026-10-13 定為第一版）：同一個鐳射 shader 裡用固定的亂數格點產生小亮點，每點只在某個角度範圍亮起，轉動時一閃一閃；用同一個 alpha 遮罩與範圍。不是粒子、不另建物件。
- 拖曳轉動、回正、展示擺動、視差位移量寫成純函式（角度夾限、慣性、回正曲線），可測試。
- 除錯入口（只在開發模式）：`window.__holo.setAngle(yaw, pitch)`，給截圖與實測用精準角度。
- 效能：像素比上限 2；只做桌機、娛樂用，不做自動降級（2026-10-13 使用者：比較重也可以；真的跑不動再從 BACKLOG 拿）。（2026-10-15 註：已加入自動降低預覽畫質，擷取一律完整畫質，見 T-809。）
- 「浮出卡外」的立體效果（角色跑出卡框）不在第一版。

### 5.3 資料與儲存

- 編輯中的卡片狀態＝一份純資料（`Card`，見 SCHEMA）＋圖片 Blob；所有編輯都是「舊狀態 → 新狀態」的純函式（方便復原／重做與測試）。
- 儲存：瀏覽器 IndexedDB 兩個表：卡片資料、圖片 Blob（以內容雜湊為 key，重複的圖只存一份）。沒用的圖只在刪卡片後和程式啟動時清（復原堆疊還可能用到）。存檔時機、容量檢查、匯入安全見 `SCHEMA.md` §3、§4。

### 5.4 卡片檔（對外唯一契約）

- `.holocard`＝zip：`card.json`（格式版本、卡片設定、圖層清單）＋`images/<雜湊>.webp`＋`preview.png`（縮圖）。
- 格式有版本號 `formatVersion: 1`；讀到較新版本 → 提示「這張卡是用較新的版本做的」，不亂開。
- OK_Games 抽卡遊戲之後讀同一格式（只讀，不寫）。

### 5.5 錯誤處理

- 上傳失敗（不是圖、檔案壞掉、超過 30 MB）→ 該檔顯示原因，其他檔照常。
- 匯入壞掉的卡片檔 → 說明哪裡壞，不覆蓋現有卡片。
- 瀏覽器不支援 3D 顯示（WebGPU 和退回用的 WebGL2 都沒有）→ 顯示說明（換瀏覽器），不白畫面。
- 自動存檔失敗（容量滿）→ 明顯提示並建議匯出。

## 6. 使用情境與驗收（BDD）

| # | 情境 | 預期 |
|---|---|---|
| B1 | 第一次開啟 | 看到範例卡，拖曳就會轉；有「新卡片」按鈕 |
| B2 | 新卡片上傳一張透明 PNG＋一張不透明 JPG | JPG 自動成為底圖、PNG 成為立體層並排在前面；轉動時角色比背景位移多（2026-10-15 註：沒有透明背景的圖會先詢問要怎麼用，不再直接成為底圖，見 T-703；沒有 AI 模型、這一面也還沒有底圖時照舊直接成為底圖，見 T-848。） |
| B3 | 只上傳不透明圖兩張 | 第一張當底圖；第二張詢問要不要取代底圖，並顯示去背提示 |
| B4 | 轉到 80°（側面）與 180° | 80° 時任何圖層都不超出卡片圓角輪廓；180° 看到背面（素色卡背或上傳的圖），看不到正面圖層 |
| B5 | 調高某層深度 | 轉動時那層位移變大、陰影變明顯；放開滑桿就存 |
| B6 | 鐳射強度 0→100 | 反光由無到明顯；範圍選「只在卡框」時角色不反光；卡框關著時沒有鐳射並有提示（2026-10-15 註：鐳射範圍已改由每面一個「反光層」決定，可選整面、用圖層形狀或上傳黑白圖，見 T-417。） |
| B7 | 拖一次深度滑桿再 Ctrl+Z | 一次就回到拖之前；連按依序還原上傳、刪除等動作 |
| B8 | 調整後立刻關掉分頁再開 | 卡片在「我的卡片」，內容和關之前一樣 |
| B9 | 匯出 .holocard 再匯入（另一個瀏覽器） | 成為一張新卡；`card.json` 去掉 id、時間後與原卡相同，畫面一樣 |
| B10 | 存成 PNG | 目前角度、畫布寬 1500 px 的圖片；可選透明背景 |
| B11 | 錄影片／GIF | 得到自動轉一圈 4±0.5 秒的 WebM 與 GIF |
| B12 | （取消：手機版不做，使用者 2026-10-13） | — |
| B13 | 上傳 40 MB 的檔 | 這個檔被拒並說明原因，其他檔照常加入 |
| B14 | 匯入被改過的卡片檔（名字含 `<script>`、數字是 NaN、多了奇怪路徑） | 拒絕或安全顯示（名字當純文字），不會執行任何東西、不影響其他卡片 |
| B15 | 鐳射開著，閃星 0→100 | 由沒有亮點到明顯；轉動時亮點一閃一閃、跟著圖層走；範圍選「只在卡框」時角色上沒有閃星 |

數字型驗收（在前景的 Chrome 量；內建窗格會被降速，不准拿來量）：桌機拖轉 60 fps（4 層、鐳射開）；開啟到可操作 < 3 秒（不含範例圖下載）。

## 7. 關鍵假設與風險（先驗證，再往下做）

| 假設 | 錯了會怎樣 | 最小驗證（M1 先做） |
|---|---|---|
| A1 平面圖層＋深度位移，在 ±35° 看起來夠立體 | 整個做法要換（例如改深度圖位移） | M1 用範例卡 3 層做原型，給使用者看能不能接受 |
| A2 新的 WebGPU 繪圖（`WebGPURenderer`＋TSL）在使用者的 Chrome 跑得順，而且擷取得到畫面（PNG／影片要用） | 改回 WebGL＋GLSL 寫法 | M1 原型回報實際用的是 WebGPU 還是退回的 WebGL2、量 fps、試擷取一張畫面 |
| A3 視差窗口做法（§5.2）在 80° 仍不穿幫、背面看不到正面 | 轉到側面時破圖 | M1 原型用 `__holo.setAngle` 截 80°、180° 檢查 |
| A4 瀏覽器儲存空間夠放幾十張卡 | 自動存失敗 | M4 存 30 張 4 層卡量用量 |
| A5 GIF 的 256 色能接受鐳射漸層 | GIF 很醜 | M5 並排比較 GIF 與 WebM，必要時 GIF 只當縮圖用 |

教訓（OK_Games 柏青哥）：模擬真實物件前先看參考；每加一個零件查有沒有擋到主體或操作；交付前和使用者參考並排比對。M1 原型就要和使用者給的參考卡並排。
